# Plan: 配置归属模型 (#8 + 环境标签 + /etc 按发行版) 与 Kali 迁移准备 → 0.4.0

## Context

准备把本机 (Arch + KDE) 积累的配置迁移到同机的 Kali (Debian 系, GNOME/gdm3, 用户名不同, uid 同为 1000). 只读检查 `/mnt/kali` 后发现, 仓库目前把 "linux" 等同于 "Arch + KDE", 直接在 Kali 上跑 bootstrap 有这些问题:

1. **归属漏洞 (issue #8)**: 用原生 `chezmoi add` 加入的目标没有登记归属, 提交检查也拦不住, 这样的目标会部署到所有平台.
2. **同一 OS 内无法区分环境**: KDE 的配置 (kwinrc, kdeglobals 等) 也会部署到跑 GNOME 的 Kali.
3. **`/etc` 只有一份 (`system/etc`, 来自 Arch)**: 在 Kali 上 restore 会把 Arch 的 `/etc` 装进去; 在 Kali 上 backup 会覆盖 Arch 的备份.
4. **迁移阻塞**:
   - `.zshrc` 有 7 处写死的家目录路径, 其中 4 处在单引号里;
   - `bootstrap.sh` 只会用 pacman 安装前置工具;
   - `bootstrap.ps1` 不会安装 scoop.

**已确认的决策**:
- `/etc` 按发行版分目录: `system/<distro>/etc`, distro 取 os-release 的 ID. `system/windows/` 预留给将来的 Windows 系统配置 (如注册表导出).
- #8 的提交时检查放进 guard.
- 迁移准备项全部带上: `.zshrc` 改用 `$HOME`; bootstrap.sh 支持 apt; bootstrap.ps1 把 scoop 作为前置工具安装.
- todo.md 放仓库根目录, 用中文.

**预期结果**: 合并后 Kali 只需要运行一次 bootstrap. 归属不会再漏登记; 环境差异用标签表达; `/etc` 各发行版互不干扰.

- **`utils/common/guard/`** (保持自成一体, 只用标准库, 支持 Python 3.9+):

  - `paths.py`:
    - 新增 `covering()`, 从 chez 移过来;

    - tree: 读工作区文件.
  - `checks.py`: 新增 `check_ownership`, 追加到 `CHECKS`.
    - 规则: `ctx.target` 存在, 不以 `/` 开头 (即不是 system 目标), `owners` 不为 None, 但没有任何列表覆盖这个目标 → 报 `error` 级的 `no-platform-owner(<target>)`.

### B2. 环境标签 `[requires]`

- **`home/.chezmoi.toml.tmpl`**: 新增 `[data] tags = [...]`.
  - Linux: `.chezmoi.osRelease.id`, 以及 `idLike` 拆分后的每一项;
  - 检测到 `lookPath "plasmashell"` 时加上 `kde`;
  - 检测到 `lookPath "gnome-shell"` 时加上 `gnome`;
  - Windows 上为空.
  - 已核实本机渲染结果: `id=arch`, plasmashell 可以找到.
- **`home/.chezmoidata/platforms.toml`**:
  - 新增 `[requires] kde = [...]`, 包括 `.config/{kdeglobals,kwinrc,kglobalshortcutsrc,kxkbrc,konsolerc,dolphinrc,mimeapps.list}`, `.local/share/konsole`, `.config/systemd/user/kwallet_auto_unlock.service`.
  - 头部注释写明: 这是给 chezmoi 读取的归属记录, 由 backup 维护; 通常只有改成 `shared`, 或者编辑 `[requires]` 时才需要手改.
- **`home/.chezmoiignore`**: 忽略集合扩展为两部分之和:
  - 另一平台的条目;
  - 本机缺少所需标签的 `[requires]` 条目.

  "只属于被忽略目标的父目录"的逻辑不变, 但本平台目标要先去掉被 requires 忽略的部分. 配置中**没有 `.tags` 时 (旧配置) 不做 requires 过滤**, 保持向后兼容. 新机器总是先生成配置再 apply, 所以不受影响.
- **`utils/common/chez.py`**:
  - `load_requires()`;
  - `base_args()` / `cz()` 新增 `tags` 参数, 合并进 `--override-data`;
  - `check_platforms()` 在每个 OS 视图中启用全部标签 (这样所有目标都可见), 并新增两项校验: 标签名必须匹配 `^[a-z0-9][a-z0-9-]*$`; 每个 requires 条目必须和某个已登记归属的条目有重叠.
- **`cli/doctor.py`**:
  - 在 chezmoi 分组中显示本机的 tags;
  - 原有的"配置文件和模板渲染结果是否一致"检查继续负责提示重新运行 `chezmoi init`.

### B4. Bootstrap

- **`bootstrap.sh`**: 有 pacman 时行为不变; 否则如果有 `apt-get`:
  1. `sudo apt-get install -y` 安装缺少的 git / chezmoi;
  2. 缺 uv 时先安装 `pipx`, 再 `pipx install uv`, 然后 `export PATH="$HOME/.local/bin:$PATH"`.

  两者都没有时, 仍然以原来的提示退出. 不执行任何远程脚本.
- **`bootstrap.ps1`**: 在 winget 安装前置工具之后加上 scoop. 只在参数里有 `--apply` 时才处理, 计划模式不需要 scoop.
  1. 下载 `https://get.scoop.sh` 到临时文件, 并打印文件路径;
  2. 询问确认 (带 `--yes` / `-y` 时跳过);
  3. 当前是管理员会话时拒绝安装并给出提示;
  4. 执行脚本, 然后 `Refresh-Path`.

  脚本保持纯 ASCII (兼容 PowerShell 5.1). 同步更新 restore 中 "scoop not installed" 的 BLOCKED 提示, 以及 reference §8 的已知限制.

### B7. todo.md (仓库根目录, 中文, 随同一个 PR 合入)

这是给在 Kali 上继续迁移的人和 agent 看的上下文提示词. 文件中不写用户名, 主机名, 绝对路径或密钥. 计划包含以下几节:

1. **目标与当前状态**: 仓库与工具的概况; 0.4.0 已经提供的归属, 标签和 `/etc` 分发行版机制.
2. **Kali 的环境事实**:
   - Debian 系, GNOME (gdm3) 加 XFCE, 默认输入法 ibus, 已装 fcitx5;
   - 已装 git, zsh, chezmoi, tmux, pipx; 默认 shell 已是 zsh;
   - home 根目录有一份权限为 755 的 age 私钥副本.
3. **操作步骤**:
   1. apt 安装软件包列表;
   2. 运行 `bootstrap.sh`: 先只看计划, 再加 `--apply`, 并用 `--key-file` 指定私钥, 用 `--skip packages` 跳过软件包;
   3. 删除私钥副本;
   4. 用 `doctor`, `check`, `apply` 验证.
4. **目标分类表**: 迁移 / 视情况 / 不迁移, 以及每类对应的标签.
5. **apt 中没有的工具**: zellij, gh, ghostty 的安装来源; GNOME 下使用 fcitx5 需要 kimpanel 扩展; 把 SSH 公钥登记到 GitHub.
6. **日常同步规则**:
   - Kali 以拉取为主: `git pull` 加 `dotfiles apply`;
   - 在 Kali 上 backup 之前先用 `-n` 审阅候选 (`backup.linux` 的候选清单两台机器共用);
   - `/etc` 会写入 `system/kali`.
7. **常见陷阱**: 配置里写 `$HOME` 但程序不会展开; re-add 去掉 `private_`; pager 卡死; 模板文件的漂移.
8. **待办 (后续版本)**:
   - apt 软件包清单 (`packages/aptpkg.txt`, 用 `apt-mark showmanual` 导出, 并按发行版恢复);
   - `system/windows/` 保存 Windows 系统配置 (注册表导出等);
   - 为 vboxclient, zeroclaw / taskdog 这类依赖特定二进制的目标增加标签;
   - 把 `.zshrc` 中的密钥拆到单独文件, 让 `.zshrc` 变成明文;
   - 迁移完成后删除 todo.md.
